# Optional contribution program — separate charter framework

GDN-135 · 17 October 2026 · implementation framework, **not an activated collection program**.

This document defines the scope that a responsible operator must adopt through a versioned program record before a private pilot can accept contributions. It does not appoint an institution, establish collection authority, claim that staff have been assigned, or authorize interviews. The contributor guidance page is available at `/contribute` on the research application. Its intake actions are not mounted.

## Purpose and choice

The program can receive existing material for private research review and separately record an optional request for program updates. An active version must state which of those purposes is permitted. A submission enters a review queue; it does not establish historical truth, rights clearance, permission to publish, ancestry, nation, or eligibility.

Each action is independent:

| Action | What it records | What it does not create |
|---|---|---|
| Read the guidance | No participation record | Consent, subscription, or enrollment |
| Acknowledge a version | The contributor understood the exact charter text and scope | A subject-specific consent grant or publication rights |
| Submit existing material | A private reference to an owned, completed, quarantined upload | Interest registration, research membership, official enrollment, or policy endorsement |
| Register program interest | A separate affirmative request for program updates | A source submission, permission to contact other family members, membership, official enrollment, or endorsement |
| Withdraw program interest | An immutable withdrawal linked to the original request | Deletion of unrelated source or acknowledgment history |

Participation must remain open to research that supports, contradicts, or complicates The Garden proposal. No program record may be used for political targeting. The implementation has no endorsement, enrollment, citizenship, eligibility, outreach, or notification operation.

## Accountable program authority

Every `contribution_program_versions` record binds the exact text and permitted collection purposes to a program ID, workspace, positive version, responsible institution, and the original research charter reference. The server-supplied authority record additionally binds the authorization ID, evidence reference, authorizing person, effective period, expiration, and confirmation of response capacity to that exact version digest.

An operator must independently verify the authority and actual response arrangements. A client checkbox, administrative role label, template institution, or synthetic test approval is not evidence of those facts. Installation requires a current scoped operator permission and recent privileged authentication. Expired, revoked, absent, mismatched, or capacity-unconfirmed authority denies collection. A change in text, institution, purpose, or authority requires a successive version; records are never overwritten.

No actual responsible institution or authorization is asserted by this framework. The application does not display a fabricated active charter.

## Exact acknowledgment and informed limits

Contributors must be able to read the complete current charter before affirmatively acknowledging it. The receipt records the exact program version and SHA-256 of its canonical text and scope. A change requires a new acknowledgment before a new submission or new interest registration. Earlier acknowledgments and contribution receipts retain their original version.

Acknowledgment is not consent to use material. Preservation, research use, attribution, display, and promotional use remain independently controlled through GDN-029. A future content-use or publication workflow must obtain its own current permitted-use decision, handle applicable rights, and preserve withdrawal rules. GDN-135 does not promote quarantined bytes into an authorized use or a reviewed claim.

## Original research scope stays intact

The original [online research completion charter](../sources/research-charter.md) remains version 1.0. Its first completion cutoff is **25 September 2026**, and it excludes new interviews and private family contact. The implementation pins the exact original charter bytes as well as its date and version. New program receipts are separately dated intake records; they do not alter the historical census, prove that an item was discoverable before the cutoff, or rewrite the preserved atlas edition.

Previously recorded oral history may be assessed as existing material only through an authorized source-classification adapter and subsequent provenance, consent, and rights review. A contributor cannot self-label new collection as historical evidence to bypass this boundary.

## Interviews and family outreach remain closed

The GDN-135 service refuses `new-interview` and unclassified upload sources. It exposes no interview, recording, outreach, or consent-capture endpoint. Future interviews require a separately authorized consent-led program, actual response capacity, and the dedicated participant consent workflow planned in GDN-137 and related community work. A program acknowledgment, archive submission, or interest request cannot substitute for that process.

This is a technical collection boundary, not a requirement to pause other engineering while waiting for an outside human security review. The owner's deferred external-review policy remains in force.

## Withdrawal and custody

Optional interest can be withdrawn without accepting a newer charter and after intake closes or the original authority expires. Authentication and ownership checks still apply. A replay of the original interest request cannot reactivate a withdrawal; a new opt-in requires a new explicit request ID and acknowledgment of the current authorized version. No messages are sent by this implementation.

The private ledger stores account references, opaque IDs, authority metadata, charter text, and audit decisions. It stores no contact addresses, genealogies, testimony, or file bytes. Original files stay in the separate upload quarantine. Append-only records preserve successful writes and withdrawals during rollback. The actual operator must provide its retention and supported request-handling process before mounting a live collection route.

## Current activation status

The code and local synthetic tests establish an implementation foundation. Production authentication adapters, real program authority, private hosted custody, response capacity, safe consent integration, and live workflow verification remain unverified. `/contribute` provides guidance and names these limits. The default-disabled service and absent API routes prevent this page from collecting personal information.

See the [operating contract](../runbooks/contribution-program.md) for adapters, verification, and rollback.

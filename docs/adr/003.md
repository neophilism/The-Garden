# ADR-003: Separate trusted processing from sealed E2EE

Status: proposed planning decision; verify integration-specific assumptions at implementation.

## Decision

Provide server-readable restricted collaboration only with explicit classification and approved encryption/key controls. Sealed mode uses recipient-controlled client-side keys; the service cannot search, OCR or send its plaintext to AI.

## Rationale

Full-text server search and operator-blind E2EE are incompatible without materially different approved protocols. This plan does not promise both transparently.

## Review trigger and limits

Canonical standard is missing: reconcile before sensitive activation. No custom crypto, false certification or silent plaintext fallback.
